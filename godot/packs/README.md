# godot/packs/

`res://packs/<id>` is where a pack that is part of the project lives: a real folder with a `pack.json`, `assets/`, `data/` and so on. The game uses one chosen pack and
the packs it is laid over; `-- --pack=<id>` chooses (section 4 of [`docs/create/CONTENT.md`](../../docs/create/CONTENT.md); the code is in
[`docs/engine/PACKS.md`](../../docs/engine/PACKS.md)).

Committed: this file and `dev/`, the developers' own pack: complete placeholder content (coloured shapes with their asset names, speech that says its own name), a short
playable campaign, and the test sectors of the engine suite. It is generated by `tools/dev_pack/`, goes into no exported game (a game carries it as `dev.larissa`, made by `pack_tool --export-pack=dev --archive`) and is not meant for play. The id `dev` is reserved.
Everything else in the folder is git-ignored.

`legacy` is the original game's content, which the importer (`uv run tools/import/import_all.py`) writes from your own copy of the game as loose files into `legacy/` here
([`docs/play/LEGACY.md`](../../docs/play/LEGACY.md)). The creature scripts, screens and sector headers in `legacy/data/sectors/` are the stored version that designers edit;
a run of the importer's `sectors` step writes the originals over edits there, and the reset tools put single things back (`docs/play/LEGACY.md`, "Putting things back: the
reset tools"). The export presets leave every pack out of an exported game; you make `legacy.larissa` yourself (`docs/play/LEGACY.md`, "Playing legacy in an exported game").

Start a pack of your own by copying dev: `tools/godot.sh --headless --path godot res://src/packs/pack_tool.tscn -- --new=<id> --from=dev` (or Project > Tools > "New pack from dev..."
in the editor). It makes `<id>/` here with new paths and uids and a `pack.json` with no `base`; import it (`tools/godot.sh --headless --path godot --import`), then
`-- --pack=<id>` plays it. A pack here goes into no exported game (a pack is a pack file next to the game, `docs/create/CONTENT.md`, "Shipping"). A pack here is trusted: it may hold `.tres` files, because it is part
of the project and its files refer to each other by `res://packs/<id>/...` paths; a pack in the data form (JSON, `.foe`, PNG, OGG) is installed into
`user://packs/` instead, and `pack_tool --export-pack=<id>` writes one from a pack here.
