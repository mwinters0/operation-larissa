# Fidelity and provenance

How the port stays checkable against the 1998 original while the repository holds none of the original's content. For building
the legacy pack as a player, see [`../play/LEGACY.md`](../play/LEGACY.md); for the formats of the game's files,
[`ASSET_FORMATS.md`](ASSET_FORMATS.md); for the original's behaviour, [`DESIGN.md`](DESIGN.md).

## The rules

- **The port follows the original as read from the asm.** `DESIGN.md` names functions by name and address
  (`tools/analysis/ghidra/names_onwin32.json`; `map_names.py find` shows an entry with its ONWIN.MAP name), never as bare `FUN_xxxx`; each statement is tagged [V] verified, [I] inferred or
  [R] reasoned.
- **A known difference is listed.** A difference a player can notice, and a deliberate deviation that refuses a visible quirk, goes
  in [`PORT_GAPS.md`](PORT_GAPS.md) (its header gives the rule). When a gap is fixed, a gdUnit4 test pins the fix and the entry is
  removed.
- **A quirk that hurts play is not copied.** The port fixes it as a **Deliberate deviation**, marked by that phrase in the code
  comment, in a test and in `DESIGN.md`; search for it to find them all.
- **Fidelity stays checkable.** Every kind of original record has an encoder, a hash fixture and a fidelity test; a change made on
  purpose is listed in the test's `DELIBERATE_*` constant with its reason.
- **Provenance is never lost.** Everything derived from the original is regenerated by the importer from the user's copy and traced
  to a CD file, resource id and offset. Hand-made layers (names, script comments, durations) are stored apart from it.
- **Fixtures commit hashes, not bytes** (below).

## The importer's rules

`tools/import/import_all.py` builds the legacy pack (`godot/packs/legacy`) from `NEPTUNE.ISO`. Steps, options and messages are in
[`../play/LEGACY.md`](../play/LEGACY.md).

- **The release check comes first.** `tools/import/source_files.json` holds the size and SHA-256 of the 31 CD files the tools read;
  `source_files.py` checks the ISO against it and a different release or a patched copy is refused before anything is read.
- **Input is the ISO, through `tools/gamefiles.py`.** The `extract` and `tables` steps make `extracted/` and the game's tables in
  `extracted/tables/`; every later step reads only those and the committed analysis in `tools/analysis/data/` (our layouts and field meanings, made with
  Ghidra, [`../../tools/analysis/ghidra/README.md`](../../tools/analysis/ghidra/README.md)).
- **Deterministic and idempotent.** Sorted keys, fixed float formatting, no timestamps; a file is written only when its content
  changes, so a second run on the same ISO changes nothing.
- **Python writes plain files.** Godot fills in its own `.import` files (`tools/godot.sh --headless --path godot --import`, which the
  last step runs). The importer writes a stub `.import` beside every asset with a uid derived from the file's path
  (`tools/import/import_uids.py`), so the same ISO gives the same uids in every checkout and a scene can refer to an asset by
  `uid://`.
- **Every asset has a recorded source.** `tools/import/asset_manifest.json` (written by the importer, committed: provenance only) says
  for every file under the pack's `assets/` its source file, resource id, offset and conversion.
- **Names, not numbers.** An asset with a registry name is written as `<name>_<number>`; a renamed one is moved and stale outputs are
  pruned ([`../create/NAMES.md`](../create/NAMES.md)).
- **Committed outputs.** The one file the importer writes into the project's `godot/data/` is `ui/menu_layout.tres`, which holds nothing of the game (the
  menu titles' x positions, measured with the theme font). The cutscenes' choreography (`data/story/`) is the original's presentation: it is the
  legacy pack's and never committed. The asset manifest and the hash fixtures are committed too. A clean import rewrites them
  with the same bytes and leaves `git status` clean.
- **Hand-made rule values.** `godot/data/rules/tuning.json` (the sub, the air and ink limits, the waits) is committed and the importer does not
  write it; `tools/import/test_import.py` pins its ink-pellet and sub-overlay tables against `extracted/tables/ink_tables.json` and
  `extracted/tables/bubbles.json`, and the engine tests pin every value (`tests/engine/test_tuning.gd`). The original's values are the defaults:
  the importer names the file nowhere and the legacy pack holds no `rules/tuning.json` (`test_the_importer_states_no_rule_values`), so
  the legacy chain resolves to exactly the project's file (`tests/legacy/test_tuning_legacy.gd`, every field and table), and the
  fidelity tests and the reachability search run on the values the chain gives.

## Fixtures commit hashes, not bytes

A committed fixture holds provenance (source file, bundle id, offset, size) and one SHA-256 of each whole record (one screen, one
sector's script), never of a field: a hash of a one- or two-byte field could be reversed by trying every value. The bytes behind it
are written by the importer from the user's copy to the git-ignored `godot/tests/fixtures/original/`, and the tests and tools that
need them say "run the importer on your copy of the game" without them. The hashes are the anchor that does not come from the
user's copy, so a different release or a patched copy is caught instead of being compared with itself.

| creature records (34 bytes each) | `FoeData.encode()`, `SectorData.encode_foe_records()` | `foe_records.json` | `test_foe_record_fidelity.gd` | `DELIBERATE_FOE_CHANGES` | `reset_foe_scripts.py N --records` |

| screen (0x500-byte record) | `ScreenData.encode()` | `screens.json` | `test_screen_fidelity.gd` | `DELIBERATE_SCREEN_CHANGES` | `reset_screens.py --all \| N \| S:M` |

- With the original bytes present a failure names the first differing byte and field ("sector 3 screen 7: first difference at byte
  0x1a3 (mid decos entry 3 y)"); without them the tests that need bytes skip with "run the importer on your copy of the game".
- The reset tools patch only the fields that are the original's record into the stored files, from the bytes in
  `godot/tests/fixtures/original/`, and check the result against the committed hash before and after writing. They refuse any
  sector but 0-31: a sector of 32 or more is its own source (`tools/import/common.py` `refuse_new_sectors`). Git cannot restore these
  files, because git does not have them.
- The creature scripts and screens of the legacy pack are the **stored version** designers edit (the screen editor, the Foe Script
  editor); a run of the importer's `sectors` step writes the originals over them, except the label names and comments kept in
  `godot/data/sectors/foe_annotations.json`.
- `src/checks/SectorChanges` (Check sector, [`../engine/EDITORS.md`](../engine/EDITORS.md)) reports per record what a sector differs in
  from the original, and shows the `DELIBERATE_*` entries as deliberate.
- Other original-data tests in `godot/tests/legacy/`: whole Voyager and Expert runs, the flow (`test_flow_fidelity_legacy.gd`), the
  cutscene timings (`test_cutscene_timing.gd`, below), the reachability sweep of every original sector,
  the snapshot comparison with reference pictures (`test_snapshots.gd`, windowed).
- Cutscene timings are pinned the same way (`godot/tests/fixtures/cutscene_timing.json`): one SHA-256 per cutscene of its **timing record**, a text of
  its length, whether it loops, every moment at which anything changes and every sound and event, in whole thousandths of a tick of the 73 Hz timer
  (`CutsceneTimingRecord`, `tests/legacy/cutscene_timing_record.gd`; `step_story.timing_record` writes the same text in Python). The legacy pack's
  timelines, the animations the scenes build from them (`test_cutscene_timing.gd`) and the importer's own timelines (`tools/import/test_story.py`) must
  all hash to the fixture, so the fixture holds no tick and a change that moves one moment fails. The one writer is
  `tools/godot.sh --headless --path godot -s ../tools/import/godot/write_cutscene_timing.gd` (from the legacy pack; run it only to move the reference).
- Voice transcripts are pinned the same way: `godot/tests/fixtures/voice_transcripts.json` holds one hash per clip transcript and the
  engine settings ([`../play/LEGACY.md`](../play/LEGACY.md), "Voice transcripts").

## Comparing with the original game

The original runs under Steam's Proton through the opt-in mise tasks of `mise.proton.toml`; installing and starting it:
[`../SETUP.md`](../SETUP.md), "For the original game under Proton". Its `patch` task installs WinG into the game directory (which
avoids installer error -115), and its `sound` task patches the game's MIDI-mapper read so that `SOUND=gm` or `SOUND=adlib` picks
the music set under Wine.
`uv run tools/analysis/register_screenshot.py IMG` finds a screenshot's crop offset, screen and sprite positions. Reading the
decompiled program: [`GHIDRA_GUI.md`](GHIDRA_GUI.md) and the call-site audit [`AUDIT_CALLSITES.md`](AUDIT_CALLSITES.md).
