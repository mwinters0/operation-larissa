# Port gaps

Known differences between the port and the original. Source: the port map `tools/analysis/ghidra/port_map_onwin32.json`, which records
for every function of ONWIN32.EXE whether the port implements it (status `not-ported`), and the names in
`tools/analysis/ghidra/names_onwin32.json`, to which the function names and addresses below refer and whose `evidence` holds the full
reading (`uv run tools/analysis/ghidra/map_names.py find <name>` shows one, ONWIN.MAP names included). Status: OPEN for a difference that is to be fixed, DEFERRED (with reason), or WONTFIX (an original quirk the port
deliberately does not copy; the code, a test and [`DESIGN.md`](DESIGN.md) mark the deviation).

The list holds every difference a player can notice that is not closed, and every **Deliberate deviation** in which the port refuses
to copy a visible quirk of the original. Keys the port adds (Delete on the sign-in screen, Space on the ballast panel) and rounding
below what a player can perceive are described in [`DESIGN.md`](DESIGN.md) only.

A gap is closed when the port matches the original, [`DESIGN.md`](DESIGN.md) describes the original behaviour (tag [V]), and a
gdUnit4 test pins it. A closed gap is removed from this list.
